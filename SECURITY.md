# Security policy

Do not publish a suspected vulnerability as a public issue. Use the repository
owner's private GitHub contact channel and include the affected URL, a minimal
reproduction, and the impact. Do not include credentials or private records.

The public surface is intentionally static. Reports concerning the shared
proxy, VPS access, or another portfolio product must name that boundary so they
can be routed without exposing unrelated infrastructure.

GitHub private vulnerability reporting is not enabled for this repository and
no public security mailbox is currently published. Until a stable private
contact is configured, use an existing private channel with the repository
owner. Never place vulnerability details in a public issue; the missing public
intake route remains an explicit operational blocker.
